<p class="lead">汇报材料最烦的不是写内容，是改内容之后的返工：一个数字变了，标题框要挪、表格要重排、页码全乱。Slidev 换了个思路——页面用 Markdown 写，浏览器负责渲染，改完保存立刻变。这篇记一下装什么、怎么写，以及在国内环境下绕不开的四个坑。</p>

## 起因：改一个数，要动十页版式

做试点考核、培训讲义这类材料，内容其实不复杂，麻烦的是两件事：

一是**反复改**。数据要等区里报上来，报一批改一批；每改一次，PPT 里的文本框就得跟着挪。

二是**版本混乱**。文件名从「终稿」到「终稿-修改-最终-v3」，最后谁也说不清哪个是发出去的。

Slidev 是这两件事的一个解法：整个演示文稿就是一个 `slides.md` 纯文本文件，用 Markdown 写。它跑在编辑器里，改完 `Ctrl+S`，浏览器里的页面立刻刷新。版式由主题接管，内容变了版式自动跟着走，不用手动挪框。

代价也要说在前面：它是网页技术栈，需要装 Node.js，不能像 PPT 那样双击就开。**如果最终交付物必须是 `.pptx` 文件，它不合适。**

## 装：先看环境，再两条命令

要求 Node.js ≥ 22.12。查一下：

```bash
node -v
```

低于 22.12 就去 Node 官网装新版。然后：

```bash
npm i -g pnpm          # 没装过 pnpm 才需要
pnpm create slidev     # 交互式，一路回车
cd <项目名>
pnpm dev               # 浏览器自动打开 localhost:3030
```

`pnpm dev` 起来之后就不用管了，改文件自动热更新。项目结构很简单：

| 路径 | 作用 |
|---|---|
| `slides.md` | **全部内容都在这里**，唯一要改的文件 |
| `package.json` | 定义 dev / build / export 几个命令 |
| `public/` | 放图片，正文里用 `/图名.png` 引用 |
| `node_modules/` | 依赖，不用管 |

## 结构：一个 `---` 就是一页

整个文件就三层，记住这三层就够了：

```md
---
theme: default
fonts:
  provider: none
  sans: 'Microsoft YaHei, PingFang SC'
---

---
layout: cover
---

# 第一页的标题

正文用普通 Markdown 写。

---

---
layout: two-cols
---

# 第二页

左栏内容

::right::

右栏内容
```

- 文件**最顶部**那一块叫 headmatter，管全局：主题、字体、翻页动画
- 每页**开头**那一块 frontmatter，只管这一页：用哪个版式
- 剩下的全是正文，Markdown 怎么写它就怎么写，表格、列表、加粗、代码块都直接可用

页与页之间靠单独一行 `---` 分隔。所以千万别在正文里随手写三条横线当分割线，它会变成翻页。

## 排版：改一个词就换版式

不需要调字号、拖文本框，换版式就是改 frontmatter 里的一个词：

| layout | 用途 |
|---|---|
| `cover` | 封面 |
| `default` | 正文，最常用 |
| `section` | 章节分隔页 |
| `center` | 居中大字，用来压一句结论 |
| `two-cols` / `two-cols-header` | 左右分栏，靠 `::left::` `::right::` 切 |
| `fact` | 放一个大数字，一页只说一件事 |
| `quote` | 引文 |
| `end` | 结尾页 |

微调样式用 UnoCSS 的原子类直接写在标签上，比如 `<div class="mt-8 p-4 border-l-4 border-blue-500 bg-blue-50">`，不用碰 CSS 文件。做汇报材料，能用到 `mt-*`（上边距）、`text-sm`（字号）、`opacity-60`（灰字）三个就差不多够了。

## 中文环境下的四个坑

这几个我都实际撞过，按顺序踩的：

| 坑 | 现象 | 解法 |
|---|---|---|
| npm 官方源 | `pnpm install` 卡在解析阶段，二十分钟不动 | 项目里放 `.npmrc` 写 `registry=https://registry.npmmirror.com`，一分钟装完 |
| 字体 | 首屏白等十几秒，中文变成难看的回退字体 | headmatter 里必须 `fonts: provider: none`，并把 `sans` 指定为 `Microsoft YaHei` 等本地字体。默认走 Google Fonts，国内拉不到 |
| markdown-it 版本 | 启动直接崩：`ERR_PACKAGE_PATH_NOT_EXPORTED ... token.mjs` | 新版 Slidev 的某个依赖 peer 要 `markdown-it@^14`，但会被装成 15。在 `dependencies` 里显式写 `"markdown-it": "^14.3.3"`，再 `pnpm install --force` |
| 正文里的尖括号 | 编译报 `Element is missing end tag` | 正文（尤其行内代码）里别直接写 `<v-click>` 这类尖括号，会被当成未闭合的 HTML 标签。要展示就用 `<code>` 包起来 |

第 3 个最费时间：报错指向生成的临时文件，看不出是版本问题，得往上翻才看到 peer 冲突的警告。

## 讲的时候：备注比页面重要

正文只放关键词，完整句子写在 HTML 注释里：

```md
## 结果判定

- 优秀：必查项全部达标，且无否决情形
- 合格：必查项基本完成

<!--
这里写口头要讲的话：等级是怎么划的、否决项有哪几条。
观众看不到，演讲者模式里看得到。
-->
```

演示时按几个键就够：

| 键 | 作用 |
|---|---|
| `空格` / `→` | 下一页 |
| `o` | 缩略图总览 |
| `p` | 演讲者模式（备注 + 下一页预览 + 计时器） |
| `d` | 画笔，可以当场在页面上划重点 |
| `f` | 全屏 |

双屏汇报的用法：主屏开 `localhost:3030/presenter`，投影那屏按 `f` 全屏。观众只看到幻灯片，自己看到备注和计时——这一套比 PowerPoint 的演讲者视图还顺一点。

## 导出：PDF 保真，PPTX 会走样

```bash
pnpm add -D playwright-chromium   # 首次导出前装一次
pnpm export                       # PDF
pnpm export-pptx                  # PPTX
```

**结论：发 PDF，别发 PPTX。**

原因是 `export-pptx` 本质是把每一页"拍平"成近似图片塞进幻灯片，表格和分栏的位置会漂，字号也不完全对得上。PDF 是浏览器直接打印，所见即所得，1:1 保真。

如果非要交 pptx（有些单位就认这个格式），建议做成"PDF + pptx 两份"，并说明以 PDF 为准。

顺带一句：`pnpm build` 会生成一个 `dist/` 静态站点目录，整个扔到任意静态服务器或内网 IIS 上就能用网址访问，手机也能看。临时分享给同事，比传文件方便。

## 它不适合什么

诚实说几条边界：

- **交付物必须是 pptx**：会走样，别硬扛
- **多人协同改稿**：Markdown 对非技术同事不友好，不如腾讯文档
- **重动画、复杂母版、嵌入 Excel 图表**：它做得到，但成本比 PPT 高
- **离线机器上临时改一页**：需要 Node 环境，不如直接开 PPT

它适合的是：**自己的讲稿、培训讲义、需要反复改数据的汇报**——内容是自己写、自己讲，改动频繁，而且要留一份可检索的纯文本存档。

## 小结

Slidev 解决的其实不是"设计"问题，是**内容与版式解耦**的问题。版式交给主题，人只管把话说清楚。一份 `slides.md` 扔进 Git，改了什么、哪天改的，一目了然——这比文件名里塞五个"最终版"要可靠得多。

我拿它做了一份四段式的汇报骨架（背景与目标 / 考核内容与方法 / 结果判定 / 下一步），改数据只动表格里的数字，其余一概不用碰。
