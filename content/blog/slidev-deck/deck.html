起因02/16

改一个数，要动十页版式

一是反复改

数据等区里报上来，报一批改一批。

每改一次，文本框得跟着挪，页码全乱。

二是版本混乱

文件名从「终稿」到「终稿-修改-最终-v3」。

最后谁也说不清哪个是发出去的。

做试点考核、培训讲义这类材料，内容其实不复杂——麻烦都在这两件事上。

换个思路03/16

整个演示文稿，就是一个纯文本文件

slides.md

  • 用 Markdown 写，一个 --- 一页
  • 浏览器负责渲染，Ctrl+S 立刻刷新
  • 需要 Node.js，双击打不开

版式交给主题

  • 内容变了，版式自己跟着走
  • 不用手动挪框、不用重排
  • 一份纯文本，扔进 Git 就有版本记录

它解决的其实不是「设计」问题，是内容与版式解耦。

代价04/16

代价先说在前面

  • 网页技术栈，要装 Node.js，不能像 PPT 那样双击就开
  • 重动画、复杂母版、嵌入 Excel 图表——做得到，成本比 PPT 高
  • 离线机器上临时改一页，不如直接开 PowerPoint

如果最终交付物必须是 .pptx 文件，它不合适。

安装05/16

先看环境，再两条命令

要求 Node.js ≥ 22.12，先查一下：

node -v

npm i -g pnpm          # 没装过 pnpm 才需要
pnpm create slidev     # 交互式，一路回车
cd <项目名>
pnpm dev               # 自动打开 localhost:3030

起来之后就不用管了，改文件自动热更新，不用重启、不用重敲命令。

安装06/16

项目里只有四个东西

路径作用
slides.md全部内容都在这里，唯一要改的文件
package.json定义 dev / build / export 几个命令
public/放图片，正文里用 /图名.png 引用
node_modules/依赖，不用管

不用记目录结构。需要改的永远是同一个文件。

结构07/16

一个 --- 就是一页

---
theme: default        # ← headmatter：管全局
fonts:
  provider: none
  sans: 'Microsoft YaHei'
---

---
layout: cover         # ← frontmatter：只管这一页
---

# 第一页标题

正文照常写。

---
  • 文件最顶部那块叫 headmatter，管全局：主题、字体、翻页动画
  • 每页开头那块 frontmatter，只管这一页：用哪个版式
  • 剩下全是正文，Markdown 怎么写它就怎么写

别在正文里随手写三条横线当分割线——它会变成翻页。

排版08/16

换版式，只改一个词

layout用途
cover封面
default正文，最常用
section章节分隔页
center居中大字，用来压一句结论
two-cols左右分栏，靠 ::left:: ::right:: 切
fact放一个大数字，一页只说一件事
quote引文
end结尾页
排版09/16

微调样式，三个原子类够用

<div class="mt-8 p-4 border-l-4 border-blue-500 bg-blue-50">
  一段说明文字
</div>
mt-*上边距 text-sm字号 opacity-60灰字

UnoCSS 原子类直接写在标签上，不用碰 CSS 文件。做汇报材料，这三个就够了。

中文环境10/16

四个坑，我都实际踩过

坑现象解法
npm 官方源装包卡在解析阶段，二十分钟不动项目里放 .npmrc 指向 registry.npmmirror.com
字体首屏白等十几秒，中文变回退字体headmatter 写 fonts: provider: none，sans 指定微软雅黑
markdown-it 版本启动直接崩：ERR_PACKAGE_PATH_NOT_EXPORTED显式写 "markdown-it": "^14.3.3"，再 install --force
正文尖括号编译报 Element is missing end tag别直接写 <v-click>，用 <code> 包起来

第三个最费时间：报错指向生成的临时文件，看不出是版本问题，得往上翻才见 peer 冲突的警告。

导出14/16

PDF 保真，PPTX 会走样

pnpm add -D playwright-chromium   # 首次导出前装一次
pnpm export                       # PDF
pnpm export-pptx                  # PPTX

PDF

浏览器直接打印，所见即所得，1:1 保真。

PPTX

每页被「拍平」成近似图片，表格和分栏的位置会漂，字号也对不齐。

发 PDF，别发 PPTX。单位非认 pptx 不可，就出两份，并注明以 PDF 为准。

边界15/16

它不适合什么

  • 交付物必须是 pptx：会走样，别硬扛
  • 多人协同改稿：Markdown 对非技术同事不友好，不如腾讯文档
  • 重动画、复杂母版、嵌入 Excel 图表：做得到，但成本更高
  • 离线机器上临时改一页：要 Node 环境，不如直接开 PPT

它适合的是：自己的讲稿、培训讲义、需要反复改数据的汇报——自己写、自己讲、改动频繁，还要留一份可检索的纯文本存档。

小结16/16

版式交给主题，
人只管把话说清楚。

一份 slides.md 扔进 Git，改了什么、哪天改的，一目了然——这比文件名里塞五个「最终版」要可靠得多。
